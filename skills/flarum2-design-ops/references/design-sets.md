# Design-sets

A design-set is the durable, versioned source of one complete look. The live forum is only ever changed by
applying a set (or rolling back to a snapshot), so any look can be recreated, compared and undone.

Location: `<repo>/design-sets/<name>/` (repo = the flarum2-ops repository root; `forum.json` → `design_sets_dir`).

## Folder layout

```
design-sets/<name>/
├── set.json          required, schema below
├── custom.less       → setting custom_less       (when "less" is set)
├── header.html       → setting custom_header     (when "header" is set)
├── footer.html       → setting custom_footer     (when "footer" is set)
├── static/           fonts/images served at /assets/design-sets/<name>/… (copied on apply)
├── images/           sources for logo / logo_dark_mode / email_logo / favicon uploads
└── screenshots/      generated by preview/screenshot (git-ignored)
design-sets/_snapshots/<id>/   automatic pre-write snapshots (git-ignored)
design-sets/gallery.html       generated comparison page
design-sets/.applied.json      which set is live, its expected theme values (drift detection)
```

## set.json

```json
{
  "name": "slate-amber",                     // = folder name, kebab-case
  "title": "Slate & Amber",
  "description": "One line for the gallery.",
  "flarum": "^2.0",
  "requires_extensions": ["fof-pages"],      // checked only; never enabled automatically
  "settings": {                              // design keys + keys of listed extensions
    "theme_primary_color": "#B45309",
    "theme_secondary_color": "#1E293B",
    "color_scheme": "auto",                  // auto | light | dark | light-hc | dark-hc
    "show_theme_selector": true,
    "theme_colored_header": true,
    "welcome_title": "Hello"                 // optional keys only change when listed
  },
  "less": "custom.less",
  "header": "header.html",
  "footer": "footer.html",
  "static": "static",
  "images": { "logo": "images/logo.png", "logo_dark_mode": "images/logo-dark.png", "favicon": null },
  "tags": { "general": { "color": "#B45309", "icon": "fas fa-comments", "description": "…" } }
}
```
(JSON has no comments; the `//` notes above are explanations only.)

### Semantics (what apply does with each field)

| Field | Present | Omitted |
|---|---|---|
| Theme keys: `theme_primary_color`, `theme_secondary_color`, `theme_colored_header`, `color_scheme`, `show_theme_selector`, `custom_less`, `custom_header`, `custom_footer` | written | **reset to Flarum's default** (colors → `#4D698E`, `custom_less` → `""`, others deleted). Switching sets is deterministic: nothing leaks from the previous set. |
| Optional keys: `forum_title`, `forum_description`, `welcome_title`, `welcome_message`, `default_route`, `show_language_selector`, `fontawesome_*` | written | untouched |
| Extension keys (`<extension-id>.<key>`) | written; the extension must be in `requires_extensions` and enabled | untouched |
| `images.<kind>` = file | uploaded (skipped when the same file was uploaded by the same set and is still live) | untouched |
| `images.<kind>` = `null` | image removed | untouched |
| `tags.<slug>.<color/icon/description>` | patched on that tag | untouched |

Keys a set can never write: image paths (`*_path`, use `images`), `extensions_enabled`, `version`,
`custom_less_error`, `assets_dirty.*`. Protected keys (mail, maintenance, drivers, secrets) are refused in sets.

### Static files and `@@ASSET:…@@`

- Allowed in `static/`: `.woff2 .woff .ttf .otf .png .jpg .jpeg .webp .gif .svg .avif .ico`. Never PHP (nginx would execute it).
- In LESS/HTML/settings write `@@ASSET:fonts/Inter-latin.woff2@@`. Apply copies `static/` to
  `<forum>/public/assets/design-sets/<name>/` (stale files of that set are pruned) and replaces the placeholder
  with `/assets/design-sets/<name>/fonts/Inter-latin.woff2?v=<sha256-8>`. The hash matters: nginx serves fonts
  with a 30-day cache, so the URL must change when the file changes.
- Placeholders inside comments are ignored; a placeholder pointing to a missing file is a validation error.

### Images

Flarum 2 accepts jpeg/png/gif/webp/bmp up to 2 MB and 24 megapixels (no SVG, no ICO). It rescales:
logo and dark logo to 60 px height (WebP, animated → GIF; small images are upscaled, so give ≥120 px height),
email logo down to ≤120×1120 px (PNG), favicon to fit 64×64 keeping the aspect ratio (PNG). Every upload
gets a new random file name and deletes the previous file. A normal logo upload also writes an email-safe
copy (`logo_email_copy_*`). **The dark-mode logo is only rendered when a normal logo exists**
(`views/frontend/forum.blade.php`: it sits inside `@if ($forum['logoUrl'])`), so a set that adds
`logo_dark_mode` also needs `logo` (validation and the upload dry run warn about this).

## Lifecycle

```
new / export ─► edit ─► validate ─► diff ─► preview (snapshot→apply→screenshots→rollback) ─► gallery
                                              │
                                              └─► apply (snapshot→write→verify; auto-rollback on failure) ─► rollback
```

### apply, step by step
1. Validate + admin check; take the write lock (`design-sets/.lock`).
2. Snapshot (settings incl. every enabled extension's keys, the served image files, tag styling, marker).
3. Copy `static/`.
4. POST `custom_less` alone. On 422 nothing else has been written; the engine restores and stops.
5. POST the remaining settings; DELETE omitted theme keys that are not CSS defaults.
6. Upload/delete images; PATCH tags.
7. Clear the cache only if a reset touched CSS or `fontawesome_*` changed (saving custom_less/colors rebuilds CSS by itself).
8. Verify: read back every key, `custom_less_error` must be empty, health (services, root/API/stylesheet 200, new log errors).
9. Write `.applied.json`; return the snapshot id, rollback command and an operations.md entry.

Any failure in 3–8 triggers an automatic rollback to the snapshot from step 2 and reports both results.
Static copies in `public/assets/design-sets/<name>/` are left in place by rollbacks (harmless, unreferenced,
versioned); the next apply of that set prunes stale files.

### rollback
Restores each key to exactly its snapshot state: value → POST, NULL → POST null, absent → DELETE; re-uploads
or deletes images whose presence changed; restores tag styling; re-saves `custom_less` if `custom_less_error`
is set; clears the cache when a CSS key was deleted; restores the marker; then re-compares (image file names
always differ after a re-upload; only presence is compared). `rollback` without an id uses the latest snapshot,
which after an apply is the pre-apply state.

### preview
Snapshot → apply → screenshots → rollback, always (also on failure). Pages: `/`, `/all`, the first discussion,
`/tags`; schemes: light/dark (browser emulation) plus light-hc/dark-hc (data-theme) when `color_scheme` is
`auto`, else the forced scheme; viewports 1440 and 390. Each shot records console errors, failed requests and
whether Flarum's loading-error fallback is visible. Visitors briefly see the previewed design while it runs.

### Drift
`.applied.json` stores the expected theme values. `doctor` reports drift when the live values differ
(someone used the admin UI). Before overwriting drifted changes, `designset export <new-name>` to keep them.

## Good set hygiene
- One look per set; name sets by look (`slate-amber`, `nordic-night`), not by date.
- Keep `custom.less` structured: fonts → palette variables → CSS custom properties → components (see template).
- Keep copy (headlines, footer text) in HTML or variables, not hard-coded in selectors.
- Commit sets to the repo; snapshots and screenshots stay git-ignored.
